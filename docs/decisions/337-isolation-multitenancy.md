## 結論(推奨)

**テナントの単位は appId。共有データに効くサーバーの動きは、作成者が公開した DSL の版だけを正とする。`runner` は専用の SA で動かし、「きっかけになったアプリの範囲だけを触れる取っ手」をコードの型で強制する。**

- **単位**: データ・実行・上限・停止は **appId** で分ける。自分だけの記録(`private`)は **(uid, appId)** で分ける(同じ appId を各自がコピーで持つため)。人(uid)は権限と「1 人あたりの上限」の軸で、テナントではない。
- **正**: 共有データ(`public` / `shared`)に効く宣言は `apps_public/{appId}` の**作成者の公開 DSL**だけ。参加者が自分のコピーを書き換えても、共有データの権限・見える範囲・自動の動きは変わらない(仲間探し #507 と同じ規則)。自動の動きは、**きっかけの時点の公開 DSL の版に固定**して動かす。止める変更(取り下げ・削除・非公開化・停止)は版に関係なく**すぐ効く**。
- **権限**: Firestore のセキュリティルールはサーバーの SDK には効かず、IAM はパス単位で絞れない(要確認: 最新の Firestore IAM 条件)。だから**範囲の強制はコードで行う**: runner のエンジンには `store.Store` 全体を渡さず、きっかけから作った「その appId に縛られた取っ手」だけを渡す。取っ手は appId を引数に取らないので、エンジンのコードは他のアプリを名指しできない。SA は `runner` 専用にし、AI の鍵などを持たせない。
- **隣人**: 1 本の共通のキューに、アプリごとの同時実行の上限とトークンバケットを重ねる(アプリごとのキューは作らない)。上限を超えたら**実行しない**(遅らせない)。停止スイッチは 全体 / アプリ / ルール の 3 段(#346)。数値は #338・#345。
- **寿命**: 退会で、端末トークンは**論理削除の時点で**消す(プッシュをすぐ止める)。自動の動きが作ったレコードは「誰のきっかけで作られたか」を持たせ、退会の消去(#458)が今の投稿と同じ規則で扱えるようにする。
- **試験**: 「別のアプリ・参加者でない人・宛先でない人にデータが届かない」「参加者が自分のコピーを書き換えても共有の挙動が変わらない」を、メモリの store とエミュレータの両方で回す表の試験にする(今の `ownerStores` の形)。

## 前提: 今の分け方

| 種類 | データの置き場 | 権限の判定 | 備考 |
|---|---|---|---|
| 自分だけ(`private`) | `users/{uid}/apps/{appId}/entities/{e}/records` | パスの uid が本人 = 本人だけ | アプリの DSL・版も同じ木 |
| 共有(`public`) | `apps_public/{appId}/entities/{e}/records` | 認証済みなら読める・書けるのは作者(`edit: members` は全員が更新) | [shared-data.md](../backend/features/shared-data.md) |
| 共有(`shared`) | 同上 | 作成者(`app_owners/{appId}`)と参加者(`apps_public/{appId}/members/{uid}`)だけ | [members.md](../backend/features/members.md)。上限 100 人 |
| シェア・探す | `shares/{token}`・`public_apps/{appId}`(DSL のスナップショット) | 発行者・掲載者 | **レコードは複製しない**。private だけのアプリは新しい appId の独立コピー([sharing.md](../backend/features/sharing.md)) |
| 仲間探し | `apps_public/{appId}/match_pairs/{pairId}`・`match_quota/{uid}` | **公開 DSL で役割を決める**・ブロックは両方向 | [matching.md](../backend/features/matching.md)(**PR #529 のマージ後にリンクが有効になる**) |

- Firestore のルールは全面拒否で、**読み書きは全部 appconfig の API を通る**([architecture.md §3](../backend/architecture.md#3-firestore-データモデル))。SSE の変化通知も appconfig が listen して流すだけ([events.md](../backend/features/events.md))。
- Cloud Run の appconfig と ai は同じ SA `run-backend` で動き([gcp-setup.md](../infra/gcp-setup.md))、退会の消去のジョブは別の SA で動く([account-purge.md](../infra/account-purge.md))。
- stg と prod は今 Firestore を共有している([#288](288-prod-staging-db-split.md))。
- 運営の非公開化は `apps_public/{appId}.hidden` で、その appId の共有データを全員 403 にする([moderation.md](../infra/moderation.md))。

## テナントの単位

### 選択肢

| 案 | 単位 | 良い | 悪い |
|---|---|---|---|
| **A. アプリ(appId)(推奨)** | 共有データ・実行・上限・停止を appId で分ける。private は (uid, appId) | 今の置き場(`apps_public/{appId}`)と同じ。停止・上限・非公開化を 1 つの鍵で扱える。#336 の「そのアプリのデータだけ」とそのまま対応 | 作成者が多数のアプリを作る場合は、作成者ごとの上限を別に置く必要がある |
| B. 人(uid) | 人ごとに全部のアプリを 1 つのテナントにする | 費用を人に付けやすい | 共有アプリは複数の人のデータが混ざるので、人では分けられない。1 人のアプリ同士の分離が無い |
| C. 共有のまとまり(参加者の集合) | 参加者の集合ごとに分ける | 「家族」「サークル」の実態に近い | 参加者は出入りするので鍵が安定しない。今のデータの置き場と合わない |

**推奨: A。** 人(uid)は「誰が読み書き・きっかけを起こしてよいか」の軸と、1 人あたりの上限(#345)の軸に使う。費用を誰に付けるかは #338。

### アプリの種類ごとの分け方

| 種類 | データ | 権限 | 実行(自動の動き) |
|---|---|---|---|
| 自分だけ(private) | `users/{uid}/apps/{appId}/…` | 本人だけ | その人のコピーの DSL の宣言が、**その人のデータだけ**に効く。テナントの鍵は (uid, appId)。宛先は本人だけ(他人宛ては共有データの宣言でしか書けない) |
| 共有・参加者(shared) | `apps_public/{appId}/…` | 作成者 + 参加者。役割(#272)・宛先(#271)も公開 DSL で決める | **公開 DSL の宣言だけ**が動く。宛先は実行の時点の参加者の中からだけ選ぶ(抜けた・外された人には届かない) |
| 共有・誰でも(public) | `apps_public/{appId}/…` | 認証済みなら読める | 公開 DSL の宣言だけ。宛先の種類を参加者より狭くする案(作者本人・ref 先の作者だけ。「全員」は無し)を #339 で決める |
| 探す(カタログ)からの追加 | private だけ → 新しい appId の独立コピー。共有を含む → 元の appId に参加 | 独立コピーは追加した人が作成者 | 独立コピーは**別のテナント**(元の作成者のルールは動かない・元のアプリの上限を食わない)。参加は元の appId のテナントに入る |
| 仲間探し(match) | `apps_public/{appId}/match_pairs`・`match_quota/{uid}` | 公開 DSL の役割・ブロック両方向・つながった相手だけ | 最初は自動の動きを付けない(付けるなら宛先は「つながった相手」だけ・つながる前の通知は出さない)。#339 で決める |

## サーバーの動きの正(どの DSL が効くか)

### 選択肢

| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| **A. 作成者の公開 DSL(推奨)** | 共有データに効く宣言(権限・一意・宛先・自動の動き)は `apps_public/{appId}` の版だけ。private の宣言は各自のコピーで、本人のデータだけ | 1 アプリ 1 つの正。責任(作成者)と費用の付け先がはっきりする。#507 と同じ | 参加者は共有の挙動を変えられない(変えたい時は作成者に頼む) |
| B. 各参加者のコピー | 書いた人のコピーの宣言で動く | 実装が今の records の検証と同じ | 参加者がコピーを書き換えるだけで、他人のデータへの権限・宛先が変わる。**採らない** |
| C. 合意制 | 参加者の承認で公開 DSL を変える | 民主的 | UI と状態が重い。需要が見えていない |

**推奨: A。** 既存の API の判定(records・SSE・印・仲間探し)もこの原則に揃っているかを、M4 の実装の前に点検し、下の試験で固める(要確認)。

### 版の固定

| 場面 | 扱い(案) |
|---|---|
| 公開 DSL の版 | 作成者のコミットで `apps_public/{appId}` が更新されるたび、サーバーの宣言だけを取り出した**変わらない版**(例: `apps_public/{appId}/rule_versions/{n}`)を作る。置き場は #341 で決める |
| きっかけ(outbox) | appconfig が書き込みと同じトランザクションで outbox に積む時に、**その時点の版の番号**を持たせる |
| 実行 | runner はその版の宣言で評価する。ただし実行の直前に「アプリが止められていないか」「そのルールが今の版でも止められていないか」を確かめ、どちらかなら**実行しない**(止める方向はすぐ効く・広げる方向は次のきっかけから) |
| 定期処理(#342) | 公開のたびに予定の一覧を作り直す(古い版の予定は消す)。実行の時点の版で評価する |

### 編集・取り下げ・削除・非公開化

| 出来事 | 自動の動き | 残っているきっかけ | データの決まり(一意・権限) |
|---|---|---|---|
| 作成者が編集(新しい版) | 新しいきっかけから新しい版 | 古い版で動く(上の「実行の直前の確認」は通す) | 書き込みの時点の公開 DSL で判定 |
| 共有の entity を無くした・取り下げ | 止める | 捨てる(実行しない) | 共有データが無くなるので対象外 |
| 作成者がアプリを削除 | 止める・予定を消す | 捨てる | `apps_public/{appId}` ごと消えるので対象外 |
| 運営の非公開化(#321) | **すぐ止める** | 捨てる。非公開を解いても後からまとめて実行しない | 共有データが全員 403 のまま |
| 運営・作成者の停止スイッチ(#346) | 止める(作成者は運営の停止を解けない) | 捨てる | 動かし続ける(止めるのは自動の動きだけ) |
| 作成者の退会(論理削除) | **止める(推奨)**。下の「決めてほしいこと」 | 捨てる | 動かし続ける(残った参加者のデータの整合のため) |
| 参加者の退出・外された | その人は宛先から外れる(実行の時点の参加者表で決める) | その人が起こした分は動く(宛先の判定で外れる) | 参加者でなくなった時点で 403 |

作成者は抜けられない([members.md](../backend/features/members.md))ので、「作成者が外された」は起きない。作成者の権利の移譲は今は無く、需要が出たら別 Issue にする。

## runner の権限(最小権限)

### 誰として動くか

| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| A. `run-backend` を共用 | appconfig・ai と同じ SA | 設定が増えない | runner の不具合で AI の鍵・ai の呼び出しまで届く。ログで区別しにくい |
| **B. `runner` 専用の SA + コードでアプリの範囲を強制(推奨)** | runner だけの SA。Firestore は DB 単位の権限、アプリの範囲は取っ手の型で絞る | 持たせる秘密を最小にできる(AI の鍵は無し・プッシュの鍵は runner だけ)。IAM の監査ログで区別できる | 範囲の強制がコード頼み → 下の多層の守りと試験で補う |
| C. アプリごとの SA・資格情報 | appId ごとに SA を作る | IAM で分かれる | SA の数の上限(要確認)と管理で現実的でない。しかも Firestore の IAM はパス単位で絞れないので、分けても範囲は絞れない |

**推奨: B。** stg の runner は #288 の分離まで**動かさないか、エミュレータ / 名前付き DB だけ**にする(共有の Firestore で stg と prod の runner が同じ outbox を拾わないように、outbox に環境の印を持たせて自分の分だけ取る)。

### コードでの強制(多層)

| 層 | 中身 |
|---|---|
| 1. 縛られた取っ手 | きっかけ(outbox の 1 件)から `AppScope{appID, ruleVersion, (private なら) uid}` を作り、エンジンにはそれだけを渡す。取っ手の読み書きのメソッドは appId を引数に取らない。エンジンのパッケージは `store.Store` 全体を import しない(import の境界を試験か lint で検査) |
| 2. 置き場の組み立ての確認 | 取っ手の中でパスを組む所は 1 か所にし、組んだパスの appId が取っ手の appId と一致しなければエラーにして記録する(起きてはいけないことの検出) |
| 3. 読むものも絞る | 読めるのは、きっかけのレコード・その ref 先・同じアプリの参加者表・宛先に決まった人の端末トークンだけ。端末トークンはアプリをまたぐ個人の情報なので、宛先の判定を通った uid の分しか引けない口にする |
| 4. 見える範囲の確認 | 通知の本文にレコードの値を差し込む前に、宛先の人がその値を API で読めるか(宛先 #271・ブロック #321・つながり #507)を同じ判定関数で確かめる。読めない人には中身を出さない |
| 5. 書いた印 | 自動の動きが書いたレコードに `origin`(ルールの ID・版・きっかけの ID・きっかけを起こした uid)を持たせる。#336 の「処理が書いたレコードではきっかけを起こさない」と、退会の消去の両方で使う。作者(`author`)の表し方は #340 / #341 で決める |
| 6. 監査のログ | 1 回の実行ごとに構造化ログ: きっかけの ID・appId のハッシュ・ルールの ID と版・処理の種類と件数・結果・かかった時間。**中身(レコードの値・本文)と生の uid は書かない**([observability.md](../infra/observability.md) と同じ)。作成者に見せる履歴(#347)は Firestore に TTL つきで別に持つ |

Firestore のデータアクセスの監査ログ(Cloud Audit Logs)を有効にするかは費用しだい(要確認)。上の構造化ログで「どのアプリの・どのルールが・何をしたか」は追える。

## 上限とうるさい隣人

### 数える単位

| 単位 | 目的 |
|---|---|
| アプリ(appId) | 1 つのアプリの暴走を止める |
| 作成者(作成者の全アプリの合計) | アプリを大量に作って上限を逃れるのを防ぐ |
| きっかけを起こした人(uid) | 1 人が大量に書き込んで他の参加者に通知を浴びせるのを防ぐ |
| 全体 | 費用のブレーカー(今の `RATE_LIMIT_GLOBAL_DAILY` と同じ考え方・[rate-limit.md](../backend/rate-limit.md)) |

数える物(実行・書き込み・通知)と値・無料 / Pro の差は **#338 と #345 で決める**。ここでは単位だけ。

### 公平に回す

| 案 | 中身 | 良い | 悪い |
|---|---|---|---|
| A. 1 本のキューを先着順 | 何も分けない | 簡単 | 1 つのアプリが詰まらせると全部が遅れる |
| B. アプリごとのキュー | appId ごとにキューを作る | きれいに分かれる | キューの数の上限・管理(要確認)。アプリの数だけ増える |
| **C. 共通のキュー + アプリごとの同時実行の上限 + トークンバケット(推奨)** | 取り出す側で appId ごとに「同時に N 件まで」「1 分に M 件まで」を守る。超えた分は**実行しない**で記録 | 1 本で済む。上限の値を変えるだけで調整できる | 取り出す側の実装が要る(#341) |

- 1 回の実行で届ける宛先の数・書くレコードの数に上限を置く(参加者は最大 100 人)。
- 失敗が続くアプリは自動で止める(回路遮断)。止まったことは作成者に出す(#347)。

### 停止スイッチ(#346)

| 段 | 誰が | 中身 |
|---|---|---|
| 全体 | 運営 | runner を丸ごと止める(`AI_PAUSED` と同じ形の環境変数・[ai-pause.md](../infra/ai-pause.md))。復元(下)の前にも使う |
| アプリ | 運営 / 作成者 | 運営の停止は作成者が解けない場所に置く(`hidden` と同じ考え方)。作成者は自分のアプリを止める・再開するだけ |
| ルール | 作成者 | 1 本だけ止める |

## データの寿命

| 対象 | 扱い(案) |
|---|---|
| 端末トークン(#269) | 退会の**論理削除の時点で**消す(30 日後の消去を待たない。プッシュをすぐ止める)。アプリの削除では消さない(人に付く) |
| 自動の動きが作ったレコード | `origin` の「きっかけを起こした uid」で引けるようにし、退会の消去は今の投稿と同じ規則(共有アプリでは残し、表示名を消す)。本人を表す情報(仲間探しのプロフィールのような)は消す側に入れる。どちらに入れるかは宣言の種類ごとに #340 で決める |
| outbox・重複防止の鍵 | TTL で消す(期間は #341)。退会の消去でも本人が起こした分を消す |
| 実行の履歴(#347) | TTL で消す。中身は持たない(ルールの ID・結果・時刻だけ) |
| 作成者の退会 | その人が作成者の共有アプリの自動の動きを止める(上の表)。他の人が使っている共有アプリのデータは今の規則どおり残す([account-purge.md](../infra/account-purge.md)) |
| 運営の非公開化 | 自動の動きを止め、残っているきっかけは捨てる。自動の動きが作った投稿も、今の `delete-record` で消せる |
| バックアップ | 今の PITR 7 日・日次 14 日([firestore-backup-restore.md](../infra/firestore-backup-restore.md))の範囲は、消したデータもバックアップには残る。**復元する時は先に runner を全体で止め**、復元した outbox が二度動かないよう、重複防止の鍵ときっかけの古さで捨てる。プライバシーポリシーの保存期間の書き方は人が確かめる |

## 隔離を試験で確かめる

試験は**表**で書く: 「誰が」×「何を」×「どのアプリの種類で」→ 期待(届く / 403 / 404 / 何も起きない)。今の `ownerStores`(メモリの store とエミュレータの両方で同じ試験を回す・`backend/internal/appconfig/share_test.go`)の形に揃える。

| 誰が | 例 |
|---|---|
| 作成者・参加者・参加していない人(appId を知っている)・外された人・ブロックした / された人・別のアプリの作成者 | 役ごとに 1 人 |

| 何を | 期待 |
|---|---|
| API の読み書き(一覧・取得・作成・更新・削除・全件削除・印) | 権限どおり。他のアプリのレコードは見えない |
| **参加者が自分のコピーの DSL を書き換える**(scope・edit・役割・宛先・ルールなど、どの項目でも) | 共有データの権限・見える範囲・自動の動きが**何も変わらない**(#507 の `TestMatchingUsesPublishedDSL` を一般化する) |
| SSE の変化通知 | 読めない人には何も流れない |
| プッシュの宛先と本文 | 宛先でない人に届かない・読めない人に中身が出ない |
| runner の処理 | きっかけのアプリ以外のデータが変わらない |
| 停止・非公開化・削除 | その後のきっかけで何も起きない |
| 退会の消去 | 端末トークン・outbox・`origin` で引ける分が規則どおり消える / 残る |

runner に足す試験:

- **語彙から作った宣言で回す試験**: 語彙の範囲で宣言を機械的に組み合わせて作り、2 つのアプリ(X・Y)に目印のレコードを置いて X のきっかけで動かす。Y のデータの要約値が変わらないこと、X の参加者以外に通知が出ないことを確かめる(乱数の種を固定してメモリの store で CI に入れる)。
- **import の境界の試験**: runner のエンジンのパッケージが `store.Store` 全体に依存していないこと。
- **環境の印の試験**(エミュレータ): stg の印の outbox を prod の runner が取らない。
- **監査のログの試験**: ログに中身・生の uid が出ないこと。

悪い依頼・悪い宣言の一覧(ai-eval に置くか試験に置くか)は #339 で決める。

## B 案(コード)を採る場合

#336 の推奨は A で、#344 は保留。C(併用)に進む場合だけ、次を別の文書で詳しく決める(ここでは方針だけ)。

| 観点 | 方針 |
|---|---|
| 資格情報 | コードを動かす場所に SA の権限も秘密も渡さない。データには上の「縛られた取っ手」を API として外に出したもの(仲介)を通してだけ触る |
| 外向きの通信 | 既定で全部止める。許可リスト(#348)だけ仲介を通す |
| CPU・メモリ・時間 | 1 回ごとに上限。超えたら止めて記録 |
| ファイル | 読み取りだけ・実行ごとに捨てる |
| 試験 | 上の表に「コードから他のアプリ・外へ届かない」を足す |

## #336 の問いへの答え

| #336 の問い | この文書の答え(案) |
|---|---|
| 共有アプリで動く宣言を「作成者の公開 DSL だけ」にする線引きでよいか | **よい**。private の宣言は本人のコピーで本人のデータだけ。きっかけの時点の版に固定し、止める変更はすぐ効く |
| 作成者が退会・外された時 | 作成者は外せない。退会(論理削除)の時点で自動の動きを**止める**(データの決まりは動かし続ける) |
| runner の資格情報 | **runner 専用の SA**。アプリの範囲はコードの取っ手で強制し、多層の守りと試験で補う |
| 暴走の単位 | アプリ・作成者・きっかけを起こした人・全体。共通のキュー + アプリごとの同時実行の上限 + トークンバケット。値は #338・#345 |
| 隔離の試験 | 役 × 操作 × アプリの種類の表。SSE とプッシュの本文も対象。メモリとエミュレータの両方 |
| stg と prod が Firestore を共有している間 | runner と定期処理は prod だけで動かす。stg はエミュレータ / 名前付き DB だけ。outbox に環境の印 |

- [ ] **版の固定**: きっかけの時点の版で動かし、止める変更はすぐ効く(推奨)
- [ ] **作成者の退会**: 自動の動きを止める(推奨) / 動かし続ける(費用の付け先は #338)

- [ ] **公平に回す方式**: 共通のキュー + アプリごとの上限(推奨) / アプリごとのキュー

- [ ] **停止スイッチ**: 全体 / アプリ / ルールの 3 段・運営の停止は作成者が解けない(推奨)
