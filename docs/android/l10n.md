# Android の文言と言語(#843)

## 文言の置き方

- 日本語が既定のリソース(`values/`)、英語は `values-en/`。文言の正は iOS の日本語の元文(`Localizable.xcstrings`)。訳を変える時は両 OS をそろえる。
- 文言はそれを使うモジュールに置く(`:app` / `:renderer` / `:services`)。
- ファイルは機能ごとに分ける: `strings_<機能>.xml`(例 `strings_voice.xml`・`strings_language.xml`・`strings_renderer.xml`)。並行する変更がぶつからないよう、共有の `strings.xml` に足していかない。
- キーは `<機能>_<意味>` の英小文字の snake_case。ファイルの中は名前順に 1 行 1 項目。
- 訳さない文言(言語名の「日本語」「English」など)は Kotlin 側に置くか、`translatable="false"` を付けて `values/` だけに置く。

## xcstrings からの移し方

手作業で移す。iOS のキーは日本語の文そのものなので、Android 側で意味の分かるキーを付け、日本語と英語をそれぞれのファイルに写す。スクリプトにしない理由: キーの付け方(どのモジュールの・どの機能の文言か)は人が決めるもので、変換の対象も画面ごとに少しずつ増えるため。

## 抜けの確認

`:app` の `StringsParityTest` が全モジュールの `src/main/res` を読み、次を確かめる。

- `values` と `values-en` のキーが同じ(`translatable="false"` は日本語だけで良い)
- 書式の引数(`%1$s` など)がそろっている
- `res/xml/locales_config.xml` の言語と `values-*` がそろっている

## アプリ内の言語

- 設定は「自動(端末の言語)/ 日本語 / English」(iOS と同じ)。自動の時は端末の好みの言語の上から ja / en の最初に当たった方、どちらも無ければ ja。
- Android 13+ は `LocaleManager` のアプリごとの言語を使う(端末の設定 > アプリ > 言語 と同じ値)。12 / 12L は自前で保存し、Activity の `attachBaseContext` で `AppLocales.wrap` を通す。新しく Activity を足す時は 12 / 12L のためにこれを入れる。
- サーバーへ送る言語(`Accept-Language` と生成・相談の `locale`)は `AppLocales.languageCode` の値。リクエストごとに読むので、切り替えはすぐ効く。
