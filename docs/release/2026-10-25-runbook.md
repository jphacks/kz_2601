## 2. 統合 PR のマージと staging の確認

## 3. develop → main のリリース PR と prod の確認

### 3.1 リリース PR を作る(作るのは誰でも・マージは人間)
```sh
git fetch origin
git log --oneline origin/main..origin/develop | wc -l     # 差分の数を控える
gh pr create --repo jphacks/kz_2601 --base main --head develop \
  --title "release: Day2 デモ版(develop → main・2026-10-25)" \
  --body-file docs/release/<本文を書いたファイル>.md     # 雛形は下
```
- `release/*` ブランチは切らない(develop を凍結して直接 main へ出す)。
- Draft にしない(Draft だと CI が走らない)。

本文の雛形(`.github/PULL_REQUEST_TEMPLATE.md` の見出し):

## 4. iOS の本番向けビルド(iPhone 16)

**Debug ビルドで入れる**。課金(PR #166)の「新規作成 1 日 3 回」は Release ビルドだけ既定で効き、Debug は既定で制限なし(設定に「回数制限を無効にする(デモ用)」が出る)。

```sh
git switch main && git pull                          # §3 でマージした main をビルドする
cd ios
./scripts/sync-firebase-plist.sh                     # GoogleService-Info.plist をリポ外からコピー
METAMON_TEAM_ID=CHP337D75C xcodegen generate         # 接続先はここでは変わらない(注意 1)
xcrun devicectl list devices                         # iPhone 16 の Identifier を控える(要確認: DEVICE_ID)

xcodebuild -scheme Metamon -configuration Debug \
  -destination "id=<DEVICE_ID>" -allowProvisioningUpdates \
  -derivedDataPath build/DerivedData \
  DEVELOPMENT_TEAM=CHP337D75C \
  METAMON_AI_BASE_URL=https://ai-prod-378953239426.asia-northeast1.run.app \
  METAMON_APPCONFIG_BASE_URL=https://appconfig-prod-378953239426.asia-northeast1.run.app \
  build

# 焼き込まれた接続先を確認(prod の URL が出れば OK)
plutil -extract MetamonAIBaseURL        raw build/DerivedData/Build/Products/Debug-iphoneos/Metamon.app/Info.plist
plutil -extract MetamonAppConfigBaseURL raw build/DerivedData/Build/Products/Debug-iphoneos/Metamon.app/Info.plist

xcrun devicectl device install app --device <DEVICE_ID> build/DerivedData/Build/Products/Debug-iphoneos/Metamon.app
```
- Team ID `CHP337D75C` は `docs/ios/architecture.md` §11 の値。`build/` は `.gitignore` 済み。
- **アプリを削除せずに上書きで入れる**(削除すると WhisperKit のモデルの再ダウンロードと、カメラ・通知の許可がやり直しになる)。初期画面に戻すのは設定の「アプリをリセット」。
- 入れたら台本 [§5.1](../03_demo_script.md#51-デモ端末iphone-16の設定チェックリスト152) を上から。**D1(接続先)は `*-prod` になっていること**(台本の D1 は「staging(既定)」のままなので、今日は prod が正)。
- Xcode の GUI で入れる場合は、Build Settings の User-Defined にある `METAMON_AI_BASE_URL` / `METAMON_APPCONFIG_BASE_URL` を prod に書き換えて ⌘R(Run は Debug)。次に `xcodegen generate` すると staging に戻る。
- 予備端末(`METAMON_MOCK=1` のモック版)は今のままでよい。

#1 のコマンド:
```sh
gcloud projects add-iam-policy-binding jphacks-kz2601 \
  --member="serviceAccount:run-backend@jphacks-kz2601.iam.gserviceaccount.com" \
  --role="roles/firebaseauth.admin"
```

## 6. 失敗した時の戻し方

**最優先の逃げ道は「iOS を staging 向けに戻す」**。staging は凍結した develop と同じ中身なので、prod だけが壊れたなら、§4 の上書きを付けずにビルド(= `project.yml` の既定 = staging)して入れ直せばよい(約 10 分)。backend を Day1 版に戻すと、今日の iOS とは機能が合わない(対話・探す などが動かない)ことに注意。

### 6.1 Cloud Run のリビジョンを前に戻す(数十秒・コードはそのまま)
```sh
# リリース前に戻す(§0 の値)
gcloud run services update-traffic ai-prod        --region=asia-northeast1 --project=jphacks-kz2601 --to-revisions=ai-prod-00001-c2d=100
gcloud run services update-traffic appconfig-prod --region=asia-northeast1 --project=jphacks-kz2601 --to-revisions=appconfig-prod-00001-l95=100
# 最新に戻す
gcloud run services update-traffic ai-prod        --region=asia-northeast1 --project=jphacks-kz2601 --to-latest
gcloud run services update-traffic appconfig-prod --region=asia-northeast1 --project=jphacks-kz2601 --to-latest
```
- §5 #2 で min-instances を変えるとリビジョンが 1 つ増える。戻し先は §3.3 で控えた一覧から選ぶ。

### 6.2 main を前のコミットに戻す(コードも戻す・prod に再デプロイが走る・約 10 分)
main に force push はしない。リリースのマージコミットを revert する PR を出す。
```sh
git fetch origin && git switch -c hotfix/revert-release origin/main
git revert -m 1 <リリース PR のマージコミット>
git push -u origin hotfix/revert-release
gh pr create --repo jphacks/kz_2601 --base main --title "revert: Day2 リリースを戻す"
```
- マージ(人間)すると deploy-cloudrun が Day1 版を prod にデプロイし直す。急ぐ時は §6.1 が先。

### 6.3 iOS だけ戻す
- staging 向けにする: §4 のコマンドから `METAMON_*_BASE_URL=...` の 2 行を外してビルド → 上書きで入れる。
- それも駄目なら台本 §4 の層 2(予備端末のモック版)→ 層 3(動画)。

### 6.4 凍結中に直したい時
`docs/02_github_workflow.md` の hotfix 手順(main から `hotfix/*` → main と develop の両方に PR)。main に push するとデプロイで `min-instances` が 0 に戻るので、§5 #2 をやり直す。

## 7. 審査 30 分前・直前のチェック

審査 30 分前:
1. `scripts/demo-check.sh prod` → 全部 OK(温めも兼ねる)。NG は表のメモを見て台本 §4 の逃げ道へ。
2. `gcloud run services describe ai-prod --region=asia-northeast1 --project=jphacks-kz2601 --format='value(spec.template.metadata.annotations)'` に `minScale=1` がある(§5 #2)。
3. 台本 [§5.1 端末チェックリスト](../03_demo_script.md#51-デモ端末iphone-16の設定チェックリスト152) を上から(D1 = `*-prod`)。

直前(台本 §6 の 10 分前):
- もう一度温めるだけなら `DEMO_CHECK_NO_AI=1 scripts/demo-check.sh prod`(Claude を呼ばない)。
- `curl -s -o /dev/null -w '%{http_code}\n' https://ai-prod-378953239426.asia-northeast1.run.app/health` → `200`(台本 §5 #5 / §6 の 2 は ai-stg と書いてあるが、今日は ai-prod を見る)。
- 主端末が初期画面(マイクのみ)・予備端末(モック)は機内モードで起動確認。

審査後: `ai-prod` を `min-instances=0` に戻す(§5 #2)。凍結を解除する。
