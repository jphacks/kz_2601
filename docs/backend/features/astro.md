# 日の出・日の入り・月齢の計算(pkg/astro・#1659)

`backend/pkg/astro` は、外の API を呼ばずに日の出・日の入り・市民薄明・月齢・月の満ち欠けを計算する純粋な関数の集まり。どこで計算するか(feed かアプリか)は #1643、feed の sun は #2136 で決める。2026-11 の時点で、ほかのパッケージからはまだ使っていない。

## 1. 関数

| 関数 | 返すもの |
|---|---|
| `Sun(year, month, day, lat, lng, loc)` | その日の南中・日の出・日の入り・市民薄明の始めと終わり(`SunTimes`)。緯度が `[-90, 90]`・経度が `[-180, 180]` の外か NaN なら `ErrInvalidLocation` |
| `Moon(year, month, day, loc)` | その日の正午の月齢と、その日の満ち欠け(`MoonDay`) |
| `MoonAge(t)` | 時刻 `t` の月齢(前の新月からの日数) |
| `PrincipalPhase(k)` | 新月・上弦・満月・下弦の時刻(UTC)。`k` が整数なら新月、`+0.25` 上弦、`+0.5` 満月、`+0.75` 下弦 |
| `Phase.Name()` / `Phase.NameJa()` | 満ち欠けの名前(`full` / 満月 など 8 つ) |

- 日の出・日の入りは太陽の上の縁が地平線に触れる時(太陽の中心が −0.833°。大気の屈折の標準の値)。市民薄明は太陽の中心が −6°。
- 観測する場所の高さ(標高)は入れていない。海面の高さとして計算する。

## 2. 式の出典

| 計算 | 出典 |
|---|---|
| 太陽の位置・均時差・日の出入り | NOAA Solar Calculator の式([NOAA の説明](https://gml.noaa.gov/grad/solcalc/calcdetails.html)) |
| 新月・上弦・満月・下弦の時刻 | Meeus『Astronomical Algorithms』第 2 版 第 49 章 |
| TT − UT(ΔT) | Espenak & Meeus の多項式(2005〜2050 年向け) |
| 月齢の定め方 | 国立天文台(NAOJ)の暦計算室と同じく、その日の正午の月齢 |

日の出入りは、南中の時刻を 3 回、日の出と日の入りの時刻をそれぞれ 4 回、その時刻の太陽の位置で計算し直して近づける(`solarNoon`・`refine`)。

## 3. 誤差の目安

テストが確かめている範囲(`backend/pkg/astro/astro_test.go`・[共通の表](../../research/astro-fixture.json))。

| 値 | 比べる相手 | 許す差 | 確かめた場所・日 |
|---|---|---|---|
| 日の出・日の入り | NAOJ「各地のこよみ」(分まで) | 1 分 | 札幌・東京・那覇(北緯 26〜43°)の 2026 年の 8 日 |
| 市民薄明 | NOAA の式で計算した値(外の表とは比べていない) | 1 分 | 同じ |
| 新月・上弦・満月・下弦の時刻 | NAOJ「暦要項」の朔弦望(分まで) | 1 分 | 2026 年の 50 回 |
| 月齢(正午) | NAOJ「各地のこよみ」東京の正午月齢(小数 1 桁) | 0.1 日 | 2026 年の 11 日 |
| その日の満ち欠け | 上の朔弦望の時刻から決めた値 | 一致 | 2026 年の 99 日 |

- 比べる相手が分まで(月齢は小数 1 桁)なので、1 分(0.1 日)より細かい精度はテストでは言えない。
- 北緯 26〜43° の外(北海道より北・赤道近く・南半球)の日の出入りは、外の表と比べていない。NOAA のページは、緯度 ±72° の間で 1 分以内・その外で 10 分以内と書いている(推測: 同じ式なので同じ程度)。
- ΔT の多項式は 2005〜2050 年向け。その外の年は月の時刻がずれる(推測: 数十年の外なら数秒〜数十秒の程度で、分の精度には効かない)。

## 4. 極地での振る舞い(白夜・極夜)

その日に太陽が地平線(−0.833°)や −6° を横切らない時は、時刻を空(`time.Time{}`・`IsZero()` が true)にし、理由をフラグで返す。

| フラグ | 意味 | 空になるもの |
|---|---|---|
| `PolarDay` | 1 日中、太陽が地平線の上(白夜) | 日の出・日の入り |
| `PolarNight` | 1 日中、太陽が地平線の下(極夜) | 日の出・日の入り |
| `CivilAllNight` | 太陽が −6° より下に沈まない(薄明が一晩中続く) | 市民薄明の始めと終わり |
| `CivilNone` | 太陽が −6° より上に上がらない | 市民薄明の始めと終わり |

- 南中の時刻はいつも返す。
- テストはトロムソ(北緯 69.6°)・ロングイェールビーン(北緯 78.2°)・マクマード(南緯 77.8°)の夏至・冬至のフラグを確かめている。この行の時刻は外の表と比べていない。
- 判定は南中の時の太陽の赤緯で 1 回だけ行う。白夜・極夜が始まる・終わる日のように、1 日の中で赤緯の変化が効く境の日は、フラグと時刻が外の表と 1 日ずれることがある(推測)。

## 5. 時間帯の扱い(日本と UTC)

- `Sun` と `Moon` は「`loc` の暦の 1 日」を受け取る。その日の 12:00(`loc`)を手がかりに計算し、返す時刻は `loc` の時刻。`loc` が nil なら UTC。
- 日本の場所は `Asia/Tokyo` を渡す(テストの表も `Asia/Tokyo`)。nil や UTC のままにしない。
- 場所の経度と合わない `loc` を渡すと、南中が 12:00 から大きく離れ、日の出や日の入りが隣の日付に入ることがある(推測)。場所の時間帯を渡す前提で使う。
- 月齢は `loc` の正午の値。同じ日でも時間帯が違えば値が変わる(東京の正午と UTC の正午は 9 時間違う)。
- `PrincipalPhase` と、内部の計算(ユリウス日・時角)は UTC。
