## 5. 直したこと

lint 再生成は OFF のままなので、生成時間を増やさない手段だけを使った。

| 種類 | 内容 | 根拠 |
|---|---|---|
| プロンプト | 記録の entity は集計(stat / chart / progressBar)していても、記録を見て直せる list(onItemTap でフォーム)をホームか別タブに必ず置く | a04(勉強記録の一覧なし) |
| プロンプト | 「済みをまとめて消す・片付ける」→ 未完了と済み(eq true)の list を section で分け、済みはスワイプで消す(一括削除の代替として申告) | a14 |
| プロンプト | 時間順・時刻順の予定は datetime の 1 field(datePicker includeTime)で sort asc。日付と時刻を別 field にしない。していない並べ方・計算を description に書かない | a16(説明の嘘) |
| プロンプト | 分類つきの記録 + 合計 → その enum の合計 chart(pie / bar・stat と同じ期間)をホームに 1 つ | a17 |
| 決定的な後処理 | 生成直後に `dsl.UnlistedEntities()`(到達できる画面に一覧が無い entity・予算などの設定 entity は除く)を見て、そのフォームを開く画面(無ければ initialScreen)に area 無しの section + list を足す。検証に通らなければ元のまま。API 呼び出しは増えない | a04 直す前(lint 再生成 OFF で行き止まりが残っていた) |
| テスト | 規則が消えないよう `TestSystemPromptHasQualityRules` に 4 つ追加。後処理は `autolist_test.go`(一覧を抜いた家計簿が直る / 完全なアプリは不変) | — |

- few-shot(docs/dsl/examples と backend の examples)は変えていない。今回の欠落は「規則が無い」ものが中心で、例を足すとプロンプトが長くなる(全ケースの入力トークン増)割に効く範囲が狭いため。カテゴリ別の chart は既存の家計簿の例にすでにある。
- 直した後の 1 周では、モデル自身が a04 の一覧を置いたので後処理は発火していない(直す前の a04 の出力に当てると一覧が足され、検証と lint を通ることを確認した)。
