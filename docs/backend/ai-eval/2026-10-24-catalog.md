# ai eval: 部品カタログのスキーマ自動生成(2026-10-24)

`prompt.go` の手書き「P0 部品カタログ」を `dsl.schema.json` の `description` / `x-usage` から生成する方式(`internal/ai/catalog.go`)に変えた後の回帰確認。手順・前回値は [2026-10-24.md](2026-10-24.md)。生 JSON は `raw/2026-10-24-claude-sonnet-5-5-low-catalog.json`。

```sh
cd backend && set -a && source ../.env && set +a
go run ./cmd/ai-eval -effort low -model claude-sonnet-5-5 -tag catalog \
  -only kakeibo_a,training_a,walk_a,reading,edit_cafe,edit_bigger_total,calendar,edit_calendar
```

## 1. 仕組み

| 層 | before | after |
|---|---|---|
| 正典 | JSON Schema(構造のみ) + `prompt.go` の手書きカタログ(用途・定石) | **JSON Schema だけ**。各 Container/Leaf に `description`(何に使うか)+ `x-usage`(area の定石)、`Container.type` / `Action.type` に `x-enumDescriptions`、特定 type 専用キーに `x-for` |
| プロンプト | 手書き箇条書き(追記漏れを誰も検証しない) | `BuildCatalog(dsl.SchemaJSON())` が起動時に生成(type: 必須 / 任意 — 用途、使い方、アクション、補助オブジェクト) |
| 検証 | なし | `catalog_test.go`: 全 Container/Leaf/Action type がカタログに出現・description/x-usage が空でない・Go の `ComponentType` 定数と一致。iOS の `ComponentRegistryTests`(schema ⇄ レジストリ)と対 |
| 生成用スキーマ | `description` を同梱 | `Relax()` が `x-*` と `description` を落とす(意味はカタログ側だけに載せる) |

## 4. 存在しない部品の要求

| ケース | 生成物 | summary |
|---|---|---|
| create「予定を登録してカレンダーで見たいアプリ」 | entity `event{title:string, start:datetime, place:string, memo:text}`。home = `A1:F2` hstack に stat「今日の予定」(count・filter today)「今月の予定」(count・thisMonth)、`A3:F10` section に **list(sort start asc・trailing start・onItemTap → form)**、`D11:F12` 追加ボタン。form は datePicker(start)+textField×3。`app.description` 末尾に「カレンダー表示は日付順の一覧で代替しました。」。存在しない type ゼロ(`dsl.Parse` 通過) | 「予定カレンダーアプリを作りました。右下のボタンから予定を追加できます。**カレンダー表示は日付順の一覧で代替しました。**」(`summarize()` が description の「代替」文を末尾に付加) |
| edit「支出をカレンダー表示にして」(kakeibo_a 基底) | patch 2 op: section title を「日付順の支出」に replace、list.item を `{title:memo, subtitle:category, trailing:date, image:receipt}` に replace。132 tokens / 1.5s | 「**カレンダー表示は日付順の一覧で代替しました。**」 |

`ai-eval` は `expect.substitution: true` で summary に「代替」が含まれることを検査する(両ケース miss 0)。

## 5. 残メモ

- create ターンは Claude が summary を書かないため、代替の一言は `app.description` 経由(`substitutionNote()` が「代替」を含む文を抽出)。`app.description` を iOS が別の場所に表示する場合は同じ文が 2 回見える。
- 代替先の指針はプロンプトに 4 例(カレンダー→日付順 list、地図→location field、タイマー→numberField、チェックリスト→toggle)。新しい代替パターンが観測されたら `list` 等の `x-usage` に足す(プロンプトではなくスキーマへ)。
- `description` を生成用スキーマから落としたので、プロパティ単位の注意書き(例: `Stat.field` 「count 以外必須」)はカタログの description / 設計原則にだけ存在する。本 eval では影響なし(stat の field 欠落ゼロ)。
