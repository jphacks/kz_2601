# ai eval: 英語の生成品質(2026-10-24・#142)

英語化(#129)で English を選ぶと generate / chat に `locale: "en"` が送られるようになったが、本物の backend で英語の生成の中身を確かめたことはなかった。日本語の品質監査([第 1 弾](2026-10-24-audit.md)・[第 2 弾](2026-10-24-audit2.md))から 12 本を英語に訳して回し、採点し、直して、もう 1 周回した。

- ブランチ: `feature/english-gen`(base `origin/develop` `f34fb75`)
- モデル: `claude-sonnet-5-5`・effort low・非ストリーム・logic pass off・**lint 再生成 OFF のまま**(ユーザー判断)
- ケース: `backend/internal/ai/eval/audit_en_cases.json`(12 本・`needs` は日本語版と同じ・`note` に元のケース id)
- 生 JSON(`raw/`): `2026-10-24-claude-sonnet-5-5-low-{audit-en-before,audit-en-after,english-cases}.json`
- API 実行: 3 周(英語 12 本 × 2 + cases.json 36 本 × 1。Claude 呼び出しは再生成込み 13 / 12 / 38)

```sh
cd backend
go run ./cmd/ai-eval -cases internal/ai/eval/audit_en_cases.json -locale en -effort low -tag audit-en-after -env-file <.env の絶対パス>
go run ./cmd/ai-audit -cases internal/ai/eval/audit_en_cases.json \
  -run ../docs/backend/ai-eval/raw/2026-10-24-claude-sonnet-5-5-low-audit-en-after.json \
  -compare ../docs/backend/ai-eval/raw/2026-10-24-claude-sonnet-5-5-low-audit-en-before.json
```

## 4. 言語の混ざりと単位

DSL の表示文字列(app / 画面 / tab / label / placeholder / emptyText / confirmMessage / enum / 通知)と summary に日本語の文字は直す前から 0。混ざりは **iOS で描画したときに出る**ものだった(DSL だけ見ると気付かない)。

| 項目 | 直す前(アプリ数) | 直した後 | iOS での見え方 |
|---|---|---|---|
| currency に unit `"$"` | 4(e01 e03 e07 e11) | 0 | numberField が `¥ 15 $`、一覧・集計は `¥15` |
| ラベル・説明文に `$` / dollars | 2(e03 e07) | 0 | "Left of $300 budget" の横に `¥120` |
| 物でない count に単位 `items` | 3(e05 e06 e09) | 0 | "Books read this year 3 items" |
| 一覧の行に boolean | 1(e09) | 0 | 「はい」「いいえ」(iOS の文字列に英訳が無い) |
| summary の英語 | "add spendings" 1 | 0 | 読み上げ |

- **通貨**: DSL の currency は円前提で iOS は常に ¥ 表示(`FieldCoding.currency`)。en の規則と en few-shot が unit `"$"` を指示していたため矛盾していた。直した後は unit を書かず ¥ に統一。**ドルで言われた金額は数値をそのまま使う**ので、"15 dollars an hour" は ¥15 / 時、"300 dollar budget" は ¥300 と表示される(説明文は "at 15 per hour" "your 300 monthly budget" のように通貨記号なしになる)。正しく見せるには iOS 側で currency の記号を unit から選ぶ変更が要る(§7)。
- **日付**: 一覧の日付は iOS が `2026-10-24` の形で出す(locale に依らない)。文言に日付を書いたケースは無かった。
- **単位**: number の unit は "min" / "h" / "kg" / "cm" / "days" と自然な英語。

## 6. 既存 cases.json の成功率とレイテンシ

比較元は第 2 弾の計測(`raw/2026-10-24-claude-sonnet-5-5-low-audit2-cases.json`・同じ 36 本)。その後 develop に入った #139 などのぶんも差に含まれる。

| 指標 | audit2-cases | 今回 |
|---|---|---|
| 成功 | 36/36 | **36/36** |
| 1 回で通過 | 33/36 | 35/36 |
| create p50 | 5,383 ms | **5,765 ms**(+0.38 秒) |
| edit p50 | 1,470 ms | 2,090 ms(**+0.62 秒**・目標超え) |
| edit p50(1 回で通過したものだけ) | 1,456 ms | 1,819 ms(+0.36 秒) |
| expect miss | 2(calendar / edit_calendar の代替言及漏れ) | 2(同じ 2 本) |

- 再生成 1 本は edit_books_rating_en で、第 2 弾でも出た「パッチの JSON の後ろに文字が続く」(`invalid character 'W' after top-level value`)が 2 回続いた(7,481 ms)。今回変えた規則とは関係ないが、英語の edit で出たのは初めて。3 周で 3 本目なので、`extractJSON` で最初の JSON 値だけを取る後処理を検討したい(自己訂正で 2 つ目の JSON を出しているなら後ろを取るべきなので、生のテキストを見てから決める)。
- edit p50 の +0.62 秒は、出力トークンが同程度(64〜132)で、増えた 874 トークンはキャッシュ読み、edit に後処理は無いことから、API の揺れが主と見ている。API 実行の上限(3 周)に達したので測り直していない。気になるなら `-repeat 3` で edit だけ測り直すのがよい。
- 日本語のケースに後処理は掛からない(`loc != en` で即 return)。日本語の規則の行は変えていない。

## 7. 残る穴

| 残り | ケース | 対応 |
|---|---|---|
| ドルで言った金額が ¥ で出る(数値はそのまま) | e03 e07 | iOS: currency の記号を field.unit("$" なら $)で選ぶ変更が要る。backend は unit `"$"` を書かせないようにしたので、iOS を直すなら en の規則と `fixEnglishUnits` の unit 削除を外す。**英語デモではドルの金額を言わない**のが安全 |

| 連続日数・通知の解釈・最新の値・予算の読み方 | e09 e12 e08 e11 | 日本語と同じ(#132 / #133) |
| e09 の 2 つ目の習慣(reading)が一覧の toggle に出ない | e09 | toggle は 1 行 1 つ。毎日くり返すチェック(#132)で解消する見込み |
