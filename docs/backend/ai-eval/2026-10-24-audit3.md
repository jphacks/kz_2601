## 4. 直したこと

lint 再生成は OFF のまま(ユーザー判断)。生成時間を増やさない手段だけを使った。

| 種類 | 内容 | 根拠 |
|---|---|---|
| プロンプト(末尾追記) | 「カテゴリ別に記録」+ 合計 / 今月 / 予算の残り → その enum の内訳 chart(pie・同じ期間)をホームに必ず 1 つ。「カテゴリ別」は内訳の依頼で「発話に無い機能」ではない | a17 |
| プロンプト(末尾追記) | resets daily は最後にやった日しか持たない。連続日数を求められたら「今日の達成数」で代替して申告。実施記録・log entity を別に足さない。直近 7 日・履歴をラベル / 説明に書かない。聞かれていない時は連続日数に触れない | a08(二重入力)・e09(嘘ラベル)・a22(聞かれていない申告) |
| 決定的な後処理(検証の前) | `fixButtonOverlap`: 一覧などの container / list / table がボタンの行まで伸びて重なっていたら、ボタンの 1 行上で終わるように縮める(2 行以上残る時だけ)。重なりは検証エラー → 再生成(+8 秒)になるので、その 1 回を省く | a01 後・e01 前と後(割り勘で 50 回中 3 回) |
| 決定的な後処理(検証の後) | `fixLayoutRules`: (1) 非フォーム画面の左下(マイクの席)にあるボタンを同じ行の右端へ。埋まっていれば toolbar へ移す(同じ action が既にあれば落とす)。(2) list の title が date / datetime なら、文字列の subtitle / trailing と入れ替える。検証に通らなければ元のまま | a06 前(マイクの席)・e03 前(日付の見出し) |
| テスト | `layoutfix_test.go`: 席のボタンが右端へ / toolbar へ(2 回かけても重複しない)/ 日付の見出しの入れ替え / 重なりが検証を通るようになる / 完全なアプリはバイト単位で不変 / 追記した規則が消えない | — |

- **prompt.go は既存の行を変えていない**(#164 がデモ発話の品質で触っているため)。`visualRules`(#146)と同じ形で `audit3Rules` を末尾に足した。
- few-shot(`docs/dsl/examples` と `backend/internal/ai/examples`)は変えていない。今回の欠落は 2 つとも「規則が無い / 規則どうしの優先が曖昧」なもので、例を足すと全ケースの入力トークンが増える割に効く範囲が狭い。カテゴリ別の pie は家計簿の例にすでにある。
- 直した後の 1 周には `fixLayoutRules` は入っていて `fixButtonOverlap` は入っていない(1 周を回したあとに再生成の原因を見て足したため)。`fixLayoutRules` を直す前の 38 本に当てると、a06 のマイクの席が直り(lint 1 → 0・summary も「右下のボタンから」に変わる)、他は不変だった。
