# ai eval: 生成前の対話フェーズ `POST /v1/chat`(2026-10-24)

Issue #74(G17)。「家計簿」のような短い発話には 1 問だけ聞き返し、要件が揃ったら `ready` で生成用の `transcript` を返す clarify ターンの品質・速度確認。生 JSON は `raw/2026-10-24-chat-claude-sonnet-5-5-low.json`(本番設定・6 ケース 8 ステップ)と `raw/2026-10-24-chat-claude-haiku-5-5-low-spot.json`(Haiku 比較 2 本)。

```sh
cd backend && set -a && source ../.env && set +a
go run ./cmd/ai-eval -chat -effort low -model claude-sonnet-5-5
go run ./cmd/ai-eval -chat -effort low -model claude-haiku-5-5 -only kakeibo_short,training_en_full -tag spot
```

## 1. 仕組み(`backend/internal/ai/chat.go`)

| 層 | 内容 |
|---|---|
| API | `POST /v1/chat {appId, messages:[{role,text}], locale?}` → `{kind:"question", text, suggestions(≤3), turn}` または `{kind:"ready", text, brief, transcript, turn}`。`DELETE /v1/chat/{appId}` で会話を消す。`openapi-ai.yaml` |
| Claude | **構造化出力**(`output_config.format` = `ChatSchema`、全プロパティ required・`additionalProperties:false`)。system prompt は固定(キャッシュ・約 1.4K tok)、user ターンに locale / ラリー数 / 会話全文。`max_tokens` 1024。JSON が壊れていたら 1 回だけ再要求 |
| 判定 | 「目的・記録する項目・見たい一覧/集計・必要なネイティブ機能」が推定できれば ready、曖昧なら最重要の 1 点だけ 20 字程度+選択肢 2〜3 個。question の時も `brief` / `transcript` を内部で持つ(次の即 ready に使う) |
| 即 ready | 最新発話が短く(ja ≤12 字 / en ≤32 字)「もう作って / それでいい / お任せ / just build it / go ahead」等を含む → **Claude を呼ばず** 直前ターンの brief / transcript で `ready`(`source:"shortcut"`)。brief がまだ無い 1 発目の「お任せで家計簿」は Claude を 1 回だけ呼んで強制 ready |
| 上限 | Claude が質問できるのは 3 ラリーまで。4 ラリー目は `## 強制 ready` を付けて呼び、質問が返っても ready に寄せる(`source:"forced"`) |
| 会話状態 | ai プロセス内 `map[appId]`(直近 10 メッセージ・TTL 30 分・アクセス時に掃除)。`messages` は全履歴でも最新 1 件でもよい(2 件以上なら置換、1 件なら追記)。appconfig への永続化(`conversations/{appId}`)は後段 |
| generate 側 | 無変更。iOS は `ready.transcript` を既存 `POST /v1/generate`(mode auto/create)に渡す |

## 3. レイテンシ

| 指標 | 値 |
|---|---|
| Claude 1 回(7 回・初回のキャッシュ作成 7.5s を含む) | **p50 2,387 ms** / p95 7,499 ms |
| 初回を除く 6 回 | 2,051〜2,618 ms(中央値 2,344 ms) |
| 即 ready(shortcut) | 0 ms(Claude 不使用) |

目標 2 秒に対して **p50 2.4 秒・やや超過**。出力 170〜240 tok のうち半分以上は question ターンでも埋める `brief` + `transcript`(即 ready の材料)で、ここを削ると「もう作って」で Claude をもう 1 回呼ぶことになる。Haiku 5.5 のスポット比較(2 本)は 2,182 / 2,772 ms と速くならず、英語の具体発話(`training_en_full`)で ready にならず質問に戻ったため **Sonnet 5.5 のまま**。Cloud Run の `min-instances=1` でキャッシュは温まるので、実機では 2 回目以降の ≈2.3 秒が体感値。

## 4. 残課題(Issue #74 に転記)

- 会話状態の永続化(appconfig `conversations/{appId}`・再起動で続きから)は後段。今は ai プロセス内 30 分 TTL
- p50 2.4 秒 → 2 秒以内にするなら question ターンの `transcript` を省略して「もう作って」時だけ 1 回追加で呼ぶ、か `effort` をさらに絞る(現状 low)
- iOS 側(#75): `kind=question` を読み上げ+`suggestions` をチップ表示、`kind=ready` なら `transcript` を既存 create へ
