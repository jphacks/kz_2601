# 2026-10-25 stat のラベルと単位の二重 + calendar の期待値(#177)

claude-sonnet-5-5 / effort low / 各 1 周。土台は feature/audit-3 + fix/demo-quality(#174 / #173)。

## 原因

- prompt.go の「count の単位」規則(「単位はラベルに書く(例 今日のセット数(回))」)を、モデルが sum の stat にも当てはめた。
- iOS の StatLeaf は count 以外の aggregate(sum / avg / max / min / latest / earliest)の値に field.unit を付ける。count は「件」、count の stat.value は単位なし。
- そのため sum(reps, unit「回」)に label「今日の合計回数(回)」を付けると「3 回」と二重になる。

## 直し方

1. プロンプト(ja / en): 単位をラベルに書いてよいのは count の stat.value だけ。sum / avg / max / min / latest は field.unit が値に付くので、ラベルに単位を書かない。
2. 決定的な後処理 `fixStatUnitLabels`(create のみ): count 以外の stat で、label 末尾の `(u)` / `（u）` が field.unit と同じなら外す。count と value モードは対象外。
3. 自動の作り直し(lint retry)には使わない(方針どおり)。
4. eval: expect `calendar`(calendar 部品があるか)と metrics `hasCalendar` / `statUnitDup` を追加。`calendar` / `edit_calendar` を `{"calendar": true, "substitution": false}` に更新した。

## 結果(全 10 ケース = 単位の確認 8 + calendar 2)

| | before | after |
|---|---|---|
| 単位が二重の stat | 1(training_a「今日の合計回数(回)」sum/回) | 0 |
| count の stat.value のラベル単位(「今年読んだ冊数(冊)」等) | 残る | 残る(意図どおり) |
| calendar / edit_calendar | calendar 部品あり・代替の申告なし(新しい expect で misses 0。古い expect なら substitution の miss になっていた) | 同じ |
| ok / firstPass / expectMisses | 10/10 / 10 / 0 | 10/10 / 10 / 0 |

- 対象: cases.json の training_a, training_b, reading, weight, nav_gym, calendar, edit_calendar と demo_cases.json の d_training, s_reading, s_medicine。
- metrics は後処理の後で測るので、after の 0 がプロンプトと後処理のどちらの効果かは分けられない。
- 1 周ずつなので発生率(before 1/8)は小さい。後処理があるので再発しても表示は直る。
- raw: `raw/2026-10-25-claude-sonnet-5-5-low-stat-unit-{before,after}{,-demo}.json`

## 残り

- count の aggregate に「記録回数」「今週の回数」のような「回」を含むラベルが付き、値は「3 件」になる例が weight / nav_gym に出た。今回の範囲外(count の単位規則の運用)。
- edit(patch)には後処理を掛けていない(他の後処理と同じ。ops と DSL がずれるため)。edit で sum の stat を足すとプロンプト頼み。
