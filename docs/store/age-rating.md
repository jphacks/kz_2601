# 年齢区分の質問票と、生成内容・共有の扱い

#329(ロードマップの R-43)。App Store Connect(ASC)の年齢区分の質問票の答えの案と根拠、利用者が作る内容・ユーザー間のやりとりの当てはめ、生成内容のフィルタの確認、未成年の扱いをまとめる。**決めるのは人**(7 章)。

- 対象の版: ① 最初の版 = 審査用の版(`Metamon-Review` / `APP_STORE_REVIEW`・共有 / 公開のデータなし・#450 #451)、② 共有を戻す版(通常の版の機能を出す時)。
- 質問票の項目と定義は、2026-11-03 に Apple の [Age ratings values and definitions](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions) と [Set an app age rating](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating) で確かめた。ASC の日本語の画面名は違うことがある(意味の近い項目に読み替える)。
- 掲載文・栄養ラベルは [listing.md](listing.md)、審査メモは [app-review-notes.md](app-review-notes.md)、却下の時の返し方は [../release/app-review-playbook.md](../release/app-review-playbook.md)。
- 法律・審査の結果を保証するものではない。推測には **(推測)** と書く。

## 1. 結論の案

| 版 | 質問票から出る区分 | 表示する区分(案) | 主な理由 |
|---|---|---|---|
| ① 審査用の版 | **9+**(「健康・ウェルネスの話題」を「はい」にした場合。「いいえ」なら 4+) | **13+**(「より高い年齢区分に変更」) | プライバシーポリシー 5 章が「13 歳未満の方を対象にしていません」。4+ / 9+ のまま出すと食い違う |
| ② 共有を戻す版 | **13+**(ソーシャルメディア「はい」)。`webView` を戻すと **16+**(無制限の Web アクセス) | 13+(`webView` を戻すなら 16+ を受け入れるか、`webView` を戻さない) | 「探す」の公開カタログ(人気順・インストール数)と、共有の投稿の「いいね」が、ソーシャルメディアの定義に当たる **(推測)** |

- ① は 13+ に上げても失うものが少ない(キッズ向けにしない・4+ / 9+ の利用者を狙っていない)。② を出す時に 13+ から下げる必要もなく、区分の変更が版ごとに揺れない。
- 区分はオーストラリアなど地域ごとに上がることがある(② のソーシャルメディアはオーストラリアで 16+)。

## 2. 質問票の仕組み(確かめた事実)

- 場所: ASC > App > 一般 > App 情報 > 年齢制限指定 >「Set Up Age Ratings」。編集は App 情報 の「編集」。Account Holder・Admin・App Manager・Marketing の役割の人が入れる。
- 流れ: アプリ内の管理と機能(capabilities)を選ぶ → 内容の各項目に頻度(なし / まれ / 頻繁)か はい / いいえ で答える → 計算された区分を見て、年齢のカテゴリと上書きを選ぶ。
- 区分は 4+ / 9+ / 13+ / 16+ / 18+。iOS 26 以降の端末で表示される(それより前の OS は別の欄)。
- **より高い年齢区分に変更(Override to Higher Age Rating)**: 計算より高い区分を選べる。表示されるのは選んだ区分で、内容の説明は質問票の答えのまま。「EULA の最低年齢が計算された区分を超えるなら、それに合わせて上書きしなければならない」。
- **キッズ向け(Made for Kids)**: 4+ / 9+ の時だけ選べて、承認後は変えられない。Tailor It は選ばない。
- 年齢の目安の URL(Age Suitability URL)は任意。

区分に効く項目(Apple の表の要旨):

| 区分 | 主な項目 |
|---|---|
| 4+ | ペアレンタルコントロール・年齢の確認・ユーザー生成コンテンツ・メッセージとチャット・広告・まれなコンテスト |
| 9+ | 健康・ウェルネスの話題・ルートボックス・まれな不敬な言葉 / ホラー / 成熟したテーマ / 空想の暴力 / 銃・武器 |
| 13+ | ソーシャルメディア・13 歳未満にソーシャルメディアを使わせない・まれなアルコール等 / 医療 / 性的な内容 / 現実の暴力 / 疑似ギャンブル・頻繁なコンテスト 等 |
| 16+ | 無制限の Web アクセス・頻繁な医療の情報・頻繁な成熟したテーマ |
| 18+ | 頻繁なアルコール等 / 性的な内容 / 現実の暴力・ギャンブル・頻繁な疑似ギャンブル |

定義の要旨(この文書の判断に効くもの):

| 項目 | 定義の要旨 |
|---|---|
| ユーザー生成コンテンツ | 利用者が作った内容を**広く配る**ことが、アプリの体験の一部になっている(広く配られる動画・写真・文・音声) |
| ソーシャルメディア | フィードや似た**見つける仕組み**で、利用者の内容を多くの人に広める・反応できる(閲覧数・いいね・コメント・シェア) |
| 13 歳未満にソーシャルメディアを使わせない | 最低限、Declared Age Range API で年齢の範囲を確かめてからソーシャルメディアの機能を有効にする |
| メッセージとチャット | アプリの機能で利用者どうしが**直接**やりとりできる(文字・音声・動画のチャット、DM・グループ、公開の投稿) |
| 無制限の Web アクセス | アプリの中で任意のページへ移動・自由に閲覧できる(埋め込みのブラウザ) |
| 年齢の確認 | 年齢の要件を満たすか確かめる仕組み(Declared Age Range API・年齢の推定・身分証) |
| 健康・ウェルネスの話題 | セルフケアや生活の提案(カロリーの記録・ダイエットの助言・運動の提案) |
| コンテスト | 利用者どうしが順位・報酬・目標の達成を競う |

## 3. 質問票の答えの案と根拠

「根拠」はコード・文書の場所。① = 審査用の版、② = 共有を戻す版。

### 3.1 アプリ内の管理・機能

| 項目 | ① | ② | 根拠 |
|---|---|---|---|
| ペアレンタルコントロール | いいえ | いいえ | 機能が無い |
| 年齢の確認 | いいえ | いいえ **(推測)** | ① は仲間探しを外した(`ClientCapabilities.reviewExcludedComponents` の `.matchList`・[review-build.md](../ios/review-build.md))。② の仲間探しは「18 歳以上」の自己申告(`MatchingAgeGate`・サーバーは `ageConfirmed` が無いと 400 `age_unconfirmed`・`backend/internal/appconfig/matching.go`)。定義の例(API・推定・身分証)に当たらないので「いいえ」。Declared Age Range API を入れたら「はい」(6 章) |
| 無制限の Web アクセス | いいえ | `webView` を戻すなら**はい** | ① は `webView` を外した。`openUrlButton` は https と決まったスキームを OS(Safari・他のアプリ)に渡すだけ(`docs/dsl/README.md` の `openUrlButton`・`dsl.OpenURLSchemes`)。② の `webView` は `WKWebView` に戻る / 進むがあり、https の任意のページを開ける(`docs/dsl/README.md` の `webView`) |
| ユーザー生成コンテンツ | いいえ | はい | ① は記録・記録帳を本人しか見ない(`sharedData` 無効で backend が scope を private に直す・`backend/internal/ai/restrict.go` の `FeatureSharedData`)。共有リンク・「探す」は外した。② は共有リンク・公開カタログ・public / shared の記録(`docs/backend/features/sharing.md`・`shared-data.md`)。当てはめは 4 章 |
| ソーシャルメディア | いいえ | **はい (推測)** | ② の「探す」は人気順(インストール数)と検索で、知らない人の記録帳を見つけてインストールできる(`GET /v1/public-apps?sort=popular`)。public の記録に「いいね」を付けられる(`entity.marks`・#255)。定義の「見つける仕組みで多くの人に広め、反応できる」に当たる |
| 13 歳未満にソーシャルメディアを使わせない | いいえ | いいえ(作るなら はい) | Declared Age Range API を使っていない(ios に呼び出しが無い) |
| メッセージとチャット | いいえ | はい | ① は人どうしのチャット(`chatThread`)と仲間探しを外した。AI に相談するチャットは相手が人ではない(定義は「利用者どうし」)。② は `chatThread`・共有アプリへの投稿・仲間探しでつながった相手の連絡先(`match: "matched"`) |
| 広告 | いいえ | いいえ | 広告の SDK なし |

### 3.2 内容

アプリが用意する文と、AI が作る画面の文(5 章のフィルタの範囲)を対象にする。利用者が自分の記録に書く文は ① では本人しか見ない。

| 項目 | ① | ② | 根拠 |
|---|---|---|---|
| 不敬な言葉・下品なユーモア | なし | なし | アプリの文言に無い。AI の生成は 5 章 |
| ホラー・恐怖 | なし | なし | 同上 |
| アルコール・タバコ・薬物の使用や言及 | なし | なし | アプリが扱う題材ではない。利用者が「お酒の量を記録」と頼めば項目名に出るが、本人の記録 **(推測)** |
| 医療・治療の情報 | なし | なし | 診断・薬の指示を出さない。AI に書かせるボタンも「医療・法律・お金の判断は断定しない」(`backend/internal/ai/text.go` の `textSystemPrompt`)。規約 2 章も同じ |
| 健康・ウェルネスの話題 | **はい(推奨)** / いいえ | 同じ | 定義の例に「カロリーの記録」「運動の提案」がある。掲載文とスクショで水分・筋トレの記録を前に出している([listing.md](listing.md) の 1・3 章)。「はい」でも 9+ で、13+ に上げるなら表示は変わらない |
| 成熟した・示唆的なテーマ | なし | なし | |
| 性的な内容・ヌード / 露骨な性的内容 | なし / なし | なし / なし | 規約 5 章で禁止。② の通報の理由に `sexual` がある(`backend/internal/appconfig/moderation.go`) |
| 空想の暴力 / 現実の暴力 / 長く露骨な暴力 / 銃・武器 | なし | なし | |
| 疑似ギャンブル | なし | なし | `randomPicker`(くじ引き)は候補から 1 件を選ぶだけで、賭けも景品も無い(`backend/internal/ai/random_rules.go`) |
| コンテスト | なし | なし **(推測)** | ① は他の人がいない。② は利用者がランキングの記録帳を作れるが、アプリが主催する競争ではない。気になるなら「まれ」(4+ のまま) |
| ギャンブル | いいえ | いいえ | お金は動かさない(`backend/internal/ai/payment_call_rules.go`: 支払いで中身を解放する仕組みを作らない) |
| ルートボックス | いいえ | いいえ | 課金なし |

### 3.3 年齢のカテゴリと上書き

| 項目 | 案 |
|---|---|
| キッズ向け | 選ばない |
| より高い年齢区分に変更 | **13+**(ポリシー 5 章に合わせる)。② で `webView` を戻すなら 16+ |
| 年齢の目安の URL | 入れない(任意)。入れるならポリシーの「お子さまの利用」 |

## 4. 利用者が作る内容・ユーザー間のやりとりの当てはめ

利用者が作る内容には 3 種類ある。

| 内容 | 誰が見るか(①) | 誰が見るか(②) |
|---|---|---|
| AI が作る記録帳(画面・項目名・見出し・説明) | 本人だけ | 共有リンクを開いた人・「探す」でインストールした人・Web の共有ページ(`/s/{token}`)を開いた人 |
| 共有アプリの記録(public / shared の entity・`chatThread`・仲間探しのプロフィール / 連絡先) | 無い(private に直す) | public = サインインした全員(匿名を含む)。shared = 作った人と招待された人 |
| 公開カタログの掲載(名前・説明・タグ・作者名) | 無い | 全員 |

### 4.1 ① 審査用の版の選択肢

| 案 | UGC | メッセージ | 良い所 | 悪い所 |
|---|---|---|---|---|
| A: UGC いいえ・メッセージ いいえ(**推奨**) | いいえ | いいえ | 定義の「広く配る」「利用者どうしが直接」に合う。審査メモの「作った物は本人だけ」(playbook 4.4)と一致する | 審査員が「AI の生成物 = UGC」と読むと 1.2 の質問が来る。その時は playbook 4.4 の返信で答える |
| B: UGC はい・メッセージ いいえ | はい | いいえ | 1.2 が「AI でコンテンツを作るアプリ」を含むことに寄せられる | 区分は 4+ のまま変わらないのに、1.2 の通報・ブロック・フィルタを求められやすい(審査用の版は通報の入口を外している)。本人しか見ない事実とも合わない |
| C: どちらも はい | はい | はい | 安全側 | 事実と違う(人どうしのやりとりが無い)。2.3.1 と食い違う |

推奨は A。審査メモの説明(本人だけが見る・共有 / 公開 / チャットは無い)と同じ事実で答える。

### 4.2 ② 共有を戻す版の選択肢

| 案 | 中身 | 区分 | 良い所 | 悪い所 |
|---|---|---|---|---|
| D: 全部戻す(**推奨**、ただし `webView` は別に決める) | 共有リンク・「探す」・public / shared・`chatThread`・仲間探し。UGC / メッセージ / ソーシャルメディア はい | 13+(`webView` で 16+) | 機能の価値をそのまま出せる | #321 の通報・ブロック・非公開化と 24 時間の対応、ポリシーと規約の追記(`docs/legal/moderation-policy-draft.md`)が先に要る |
| E: 招待制だけ戻す | 共有リンク・shared だけ。「探す」と public・仲間探しは出さない。UGC / メッセージ はい・ソーシャルメディア いいえ | 4+ 〜 9+(上書きで 13+) | 知らない人と出会わない。ソーシャルメディアに当たらない | 「探す」・仲間探しが使えない。招待した人どうしでも通報・ブロックは要る(1.2) |
| F: 当面戻さない | ① のまま | ① と同じ | 運用が軽い | 共有の機能が出せない |

- `webView` は ② でも外したままにするか、開ける先を決まったドメインに絞る作りにすれば、16+ を避けられる **(推測。絞り方が「無制限」に当たらないかは Apple の判断)**。
- 仲間探しは本体の区分(13+)の中で 18 歳以上の自己申告を求めている。恋愛・出会い目的は作らない([../backend/features/matching.md](../backend/features/matching.md))ので、出会い系の扱い(17+ / 18+)にしない方針。

## 5. 生成内容のフィルタの確認

不適切な画面・文言を作らないための仕組みを、層ごとに並べる。

| 層 | 何をするか | 場所 | 効く版 |
|---|---|---|---|
| モデル | Anthropic の Claude(既定 `claude-sonnet-5-5`)。利用ポリシーに沿わない依頼はモデルが断る(`stop_reason: refusal`)。Haiku 以外は断った時の代わりの応答(fallbacks)を使う | `backend/internal/ai/client.go` | 全部 |
| 断りの扱い | 断った時は記録帳を作らず、`refused` の誤りで返す(生成・相談・AI に書かせるボタン)。ログの結果は `refused` | `generate.go`・`chat.go`・`text.go`・`generate_log.go`・`usage_log.go` | 全部 |
| プロンプトの決まり: 恋愛・出会い | 恋人探し・婚活・出会い系は作らず、理由の一文を説明に書く。恋人・家族の間の記録は作る | `matching_rules.go` の `datingRules` / `datingChatRule` | 全部 |
| プロンプトの決まり: お金 | 支払いで中身を解放する仕組み・支払いの画面・アプリ内の通話を作らない | `payment_call_rules.go` | 全部 |
| プロンプトの決まり: 投稿者 | public / shared に名前の手入力欄を作らない(なりすましを防ぐ) | `prompt.go`(#250 #251) | ② |
| プロンプトの決まり: 仲間探し | プロフィールに写真・位置・連絡先・年齢・性別・学校を入れない。中高生の仲間探しは招待制の shared にする | `matching_rules.go` の `matchingRules`、[matching.md](../backend/features/matching.md) | ② |
| プロンプトの決まり: AI に書かせるボタン | 暴力・自傷・違法・危険・性的・差別や誹謗中傷・個人を攻撃する内容は書かない。医療・法律・お金は断定しない。反する指示には「この内容は書けません」と返す | `text.go` の `textSystemPrompt` | オンライン版は ②(① は端末内 AI だけ) |
| サーバーの検証 | 生成物を JSON Schema と DSL の検証にかけ、問題があれば作り直す。恋愛・出会いの依頼で断りの一文が無ければ足す(`datingOmission`) | `generate.go`・`omission.go`・`matching_rules.go` | 全部 |
| 版の制限(restrict) | 版が描けない部品・機能(① の共有・チャット・仲間探し・`webView` 等)をプロンプトと schema から外し、出力に残れば直す。内容の良し悪しではなく、版の機能の範囲を守る | `restrict.go`(`enforceRestriction`) | ① |
| 公開の後 | 通報(理由: スパム・性的・暴力・嫌がらせ・違法・プライバシー・その他)・ブロック・運営の非公開化 | `appconfig/moderation.go`・`cmd/moderate`・`docs/infra/moderation.md`(#321) | ② |
| ai-eval | 恋愛・出会いの依頼を断るか(作成 2 件・チャット)、恋人同士の記録は作るか(作成 1 件)を見るケースがある(`internal/ai/eval/matching_cases.json`・`matching_chat_cases.json`、期待値は `cmd/ai-eval/matching.go`)。それ以外の不適切な依頼(暴力・性的・違法など)のケースは無い。実 API で回した結果の記録は `docs/backend/ai-eval/` に無い | `backend/cmd/ai-eval` | — |

まとめ:
- ① では、作った物は本人しか見ないので、生成内容が他の人に届くことは無い。生成の安全は、モデル自身の判断と、上の決まりに頼っている。
- ② では、作った記録帳と記録が他の人に届く。区分の答え(3 章)が成り立つには、公開の後の仕組み(#321)と、公開の前の確かめの両方が要る。どこまで入れるかは 7 章。
- 審査メモ・返信に「生成の前後で不適切な内容を作らないようにしている」と書くのは、7 章の 3〜5 が決まってから(playbook 4.4 の注のとおり、確かめていない事実は書かない)。

## 6. 未成年の扱い

今の決まり:

| どこ | 中身 |
|---|---|
| プライバシーポリシー 5 章 | 13 歳未満の方を対象にしていません |
| 利用規約 | 年齢の決まりは無い |
| 仲間探し(②) | 「つながりたい」を送る・承認するには 18 歳以上の自己申告。年齢は保存しない。中高生の仲間探しは招待制の shared([matching.md](../backend/features/matching.md) の 7 章) |
| アプリ | 年齢を聞く画面・Declared Age Range API は無い |

### 6.1 区分

| 案 | 中身 | 良い所 | 悪い所 |
|---|---|---|---|
| 13+ に上書き(**推奨**) | 3.3 のとおり | ポリシーと一致。② の 13+ と揃い、版で区分が下がらない | 13 歳未満は(保護者の設定次第で)入れられない。もともと対象外 |
| 計算どおり(4+ / 9+) | 上書きしない | 入れられる人が多い | ポリシーの「13 歳未満は対象外」と食い違う。② で 13+ に上がる |

### 6.2 共有・公開・仲間探し(② の時)

| 案 | 13〜17 歳 | 良い所 | 悪い所 |
|---|---|---|---|
| G: 区分 13+ のまま、仲間探しだけ 18 歳以上の自己申告(**推奨・今の作り**) | 共有リンク・「探す」・public の投稿は使える。仲間探しの「つながりたい」は使えない | 作り直しが要らない。知らない人と連絡先を交換する所だけ大人に絞る | 自己申告なので年齢は確かめていない。「探す」と public の投稿は 13〜17 歳も見る・書く |
| H: G + Declared Age Range API | 年齢の範囲で、仲間探し(と、必要なら「探す」への掲載・public の投稿)を出し分ける | 「13 歳未満にソーシャルメディアを使わせない」「年齢の確認」に「はい」と言える。自己申告より強い | iOS 26 以降の API。作る費用と、範囲を共有しない利用者の扱いを決める必要がある |
| I: 区分を 16+ / 18+ に上げる | 使えない | 未成年の配慮が要らない | 利用者が大きく減る。記録帳の本体には要らない制限 |
