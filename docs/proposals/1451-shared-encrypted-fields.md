## 1. 今の作り

| 所 | 中身 |
|---|---|
| 鍵 | iOS の `FieldCipher.swift`(`MetamonServices/Local/`)。256bit の対称鍵 1 本を iCloud キーチェーンに置く(`service = jp.kz2601.metamon.field-key`・`account = v1`・`kSecAttrSynchronizable`・`AfterFirstUnlock`)。**利用者ごとに 1 本で、アプリごとではない**。同じ Apple ID の端末(iPhone・Mac)は同期で同じ鍵を読む |
| 暗号 | AES-GCM。レコードの値は `enc:v1:<base64(nonce + 暗号文 + tag)>`(backend の `dsl.EncryptedPrefix` と同じ)。**封筒に鍵の番号は無い** |
| 鍵を作る時 | `RecordSyncEngine` が、その entity にまだ読めない暗号文が無い時だけ鍵を作る(別の端末の鍵の同期を待つ。作ると鍵が 2 本になるため) |
| 読めない時 | 値の代わりに「この端末ではまだ読めません」の文を出し、そのまま保存し直されても暗号文を残す。鍵が無くて暗号化できない値は保存も送信もしない |
| DSL の検査 | `backend/pkg/dsl/encrypted.go`: string / text だけ・computed / hidden / defaultValue / unique に使えない・式・filter・sort・集計・serverRules・オンラインの AI・nearbyShare から読めない。**entity が shared / public なら弾く**(他の人は鍵を持たないため) |
| AI の決まり | `backend/internal/ai/encrypted_fields_rules.go`: 版が `field.encrypted` を送った時だけ「private のアプリだけで使う」と書き、送らない版には encrypted を消して申告させる |
| 版の印 | iOS の `ClientCapabilities.swift` が `field.encrypted` を送る。Android は `DeviceCapabilities.kt` で `implemented = false`(作っていない)。デスクトップにも実装は見当たらない |
| 課金 | `backend/internal/paid/paid_features.json` の `encryptedFields`(Pro の機能) |
| 通話との関係 | callButton は「共有のアプリだけ」(`call_button_rules.go`)。暗号化した項目は private だけ。だから 1 つのアプリで一緒に使えない(#1395) |

## 2. 共有で使う時に変わること

- 鍵は「利用者ごと」から「**アプリ(appId)ごと**」に変える必要がある。今の利用者の鍵を参加者に渡すと、その人の他のアプリも読めてしまう。
- 封筒に**鍵の世代の番号**が要る(作り直した後に古い鍵・新しい鍵のどちらで開くか分かるように)。`enc:v2:<世代>:<base64>` のような新しい形と、`supportedFeatures` の新しい印(例: `field.encrypted.shared`)が要る。`enc:v1` は今のまま読めるようにする。
- iCloud キーチェーンは同じ Apple ID の端末にしか届かない。別の人に届ける道を別に作る。
- Android・デスクトップは暗号化そのものをまだ持たない。共有のアプリに Android の参加者がいると読めない人が出る(推測: 当面は「iOS・Mac の参加者だけ」か「参加者全員が対応版になるまで encrypted を足せない」のどちらかが要る → 決めること)。

## 3. 選択肢

| 選択肢 | 中身 | 弱み |
|---|---|---|
| A. 端末ごとの公開鍵 + アプリの鍵の包み直し | 各端末が鍵の組を作り、公開鍵をサーバーに置く。アプリの鍵(対称鍵)を参加者の端末ごとに公開鍵で包んでサーバーに置く。参加・外す・端末を替えた時に包み直す | 作る量が一番多い。サーバーが渡す公開鍵が本人の物かを確かめる手段(鍵の指紋を見比べるなど)が無いと、サーバーを信じる前提になる。参加者の端末の全部がオンラインで鍵を受け取るまで読めない時間がある |
| B. 共有の合言葉 | 作成者が合言葉を決め、参加者にアプリの外(口頭・別のメッセージ)で伝える。端末は合言葉から鍵を作る(塩と世代はサーバーに置く) | 合言葉が弱いと守りが弱くなる。伝え方を利用者に任せる。外した人を止めるには合言葉を変えて全員に伝え直す。合言葉を忘れると誰も読めない |
| C. 作らない | 今のまま private だけ。共有で隠したい値は「共有にしない」で案内する | #1451 のやりたいこと(共有 + 暗号化・通話と一緒)はできない |

## 4. 要るもの 5 項目 × 選択肢

| 要るもの(#1451) | A. 公開鍵 + 包み直し | B. 共有の合言葉 | C. 作らない |
|---|---|---|---|
| 1. 参加者に鍵を配る | 参加した時に、包める参加者(作成者・管理者のどちらかで決めること)の端末が新しい参加者の端末ごとに包んで置く。包む人がオンラインになるまで新しい参加者は読めない | 配らない。参加者が合言葉を入れる。アプリの外で伝える | 配らない |
| 2. 外した時の作り直し | 新しい世代の鍵を作り、残った参加者の端末ぶん包み直す。以後の書き込みは新しい世代。古い記録を新しい鍵で書き直すか(端末の作業量が大きい)は決めること。外した人が既に読んだ値は取り戻せない(どの方式でも同じ) | 合言葉を変えて残った人に伝え直す。同じく古い記録の書き直しは決めること | 無い |
| 3. 新しく入った人が前の記録を読めるか | 渡す世代を選べる。「全部の世代を渡す(前の記録も読める)」か「今の世代だけ(入った後だけ)」か → 決めること | 合言葉が同じ世代の記録は読める。世代を分けたい時は合言葉を変える | 無い |
| 4. 端末を替えた・失くした時 | 新しい端末は公開鍵を置き、他の参加者の端末(または同じ人の別の端末)が包み直すまで読めない。失くした端末の公開鍵はサーバーから消し、作り直す(2 と同じ)。iCloud キーチェーンで同じ人の端末に鍵の組を同期させれば、替えた時は待たずに読める(推測: 失くした時の扱いとの兼ね合いは決めること) | 合言葉をもう一度入れれば読める。失くした端末が合言葉から作った鍵を持ったままなので、止めるには合言葉を変える | 今のまま(iCloud キーチェーンで同じ Apple ID の端末へ) |
| 5. AI の決まりと版 | `encrypted.go` の shared の弾きを「新しい印を送る版で、かつアプリが鍵の配り方を持つ時」に限って外す。`encrypted_fields_rules.go` に shared 用の 1 文を足し、新しい印を送らない版には今の文(private だけ)のまま。callButton と同じアプリを許すのはこの時だけ | A と同じ。加えて合言葉を入れる画面が要ることを AI が案内する文 | 今のまま。#1395 の弾きを残す |

## 5. サーバーに置く物・端末の作業量

| | A | B | C |
|---|---|---|---|
| サーバーに置く物 | 端末の公開鍵(利用者の木の下)・アプリの鍵の世代・世代 × 端末ごとの包んだ鍵(`apps_public/{appId}` の下)。どれも平文の値は持たない | 鍵の世代と塩(合言葉の確かめに使う値を置くかは決めること)。合言葉そのものは置かない | 無し |
| 端末の作業量(iOS) | 大: 鍵の組・包む / 開く・包み直しの順番待ち・世代の切り替え・鍵の指紋を見せる画面(作るかは決めること) | 中: 合言葉の入力・忘れた時の案内・世代の切り替え | 無し |
| backend の作業量 | 中: 公開鍵と包んだ鍵の口・参加 / 外す時の「包み直し待ち」の印・DSL の検査の変更 | 小: 世代と塩の口・DSL の検査の変更 | 無し |
| Android・デスクトップ | どちらも暗号化から作る(今は無い) | 同じ | 無し |

## 6. 推奨(案)

- 推奨は **A**。理由: 参加者に作業(合言葉を伝える・覚える)をさせず、外した時に残った人の操作が要らない。#1451 の「要るもの」も A の形(端末ごとの公開鍵とアプリごとの鍵)で書かれている。
- 段階: (1) 封筒に世代を入れる `enc:v2`(private でも使う・読めるのは今と同じ人)→ (2) iOS・Mac だけで A → (3) Android・デスクトップ。
- 3(前の記録)は「今の世代だけ」を推奨(推測: 隠したい値を後から入った人に見せない方が驚きが少ない)。

## 7. 決めてほしいこと

| 選択肢 | 意味 |
|---|---|
| A で進める(推奨) | 端末ごとの公開鍵 + アプリの鍵の包み直し。作る量は多いが参加者の作業が無い |
| B で進める | 共有の合言葉。作る量は少ないが、伝える・忘れる・外した時の伝え直しを利用者に任せる |
| C(作らない) | 今のまま private だけ。#1451 を閉じる |
| 明日に送る | 今日は決めない |

A・B のどちらかに決めた後に決めること:

| 項目 | 候補 |
|---|---|
| 新しく入った人が前の記録を読めるか | 今の世代だけ(推奨) / 全部の世代 |
| 外した時に古い記録を新しい鍵で書き直すか | 書き直さない(以後の書き込みだけ新しい世代・推奨) / 書き直す |
| 鍵を包める人(A) | 作成者と管理者(推奨) / 参加者の誰でも |
| Android・デスクトップの参加者がいる時 | encrypted を足せない / 読めない人がいてもよい(値は「読めません」) |
| 鍵の指紋を見比べる画面(A) | 作る / 作らない |
