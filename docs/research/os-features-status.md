## 読み方

| 書き方 | 意味 |
|---|---|
| 済み #N | 生成アプリや OS から使える形で epic/god に入っている。#N は Issue 番号 |
| 口だけ #N | 読み取り・書き込みの口(コード)は入っているが、部品・式・アクションにはまだ出していない |
| 未着手 #N | コードが無い。#N は作る Issue(Issue が無い OS は、まとめの子の Issue の番号) |
| 調べ済み #N | 調べて結論を書いた(使えない・見送りなど)。作る物は無い |
| - | そのまとめの子の Issue に、その OS の分が無い(対象外と決めたわけではない) |

- 項目の名前の末尾の `#N` は、まとめの Issue に並んでいる子の Issue です。
- 表は 1 行 1 項目で、項目の名前順です(まとめごとに表を分けています)。
- 作業中の PR(まだ epic/god に入っていない物)は「未着手」に入れ、備考に書きます。

## 決めること

- 決めること: まとめの Issue のチェックを、この表に合わせて更新する(まとめの Issue の本文を直すのは人の作業)。
- 決めること: 「口だけ」(連絡先 1 人・電池・画面を消さない)を部品・式にするかは、判断材料の下書き(#2149・#3026・#3029・#3030)の結論を待つ。この表は決めない。
- 推測: 「済み #2000」(記録の文字の翻訳)と「済み #1993」(コントロール)は、Issue が開いたままだが、実装は epic/god に入っている。`develop` に入ったら Issue を閉じてよいかは確かめていない。
