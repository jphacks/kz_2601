## 言語の決め方

`Lang.resolve` が起動時に 1 回決める(`Strings.lang`)。

1. `-Dtailorit.lang=<タグ>` か環境変数 `TAILORIT_LANG=<タグ>` があればそれ(system property が先)
2. 無ければ OS の表示の言語(`Locale.getDefault(Locale.Category.DISPLAY)`。Windows は表示言語)
3. タグが `ja` で始まれば日本語(`Lang.JA`)、それ以外は全部英語(`Lang.EN`)。適合テストの `device.locale` と同じ規則

テストは `Strings.withLang(Lang.EN) { … }` で一時的に替える。デスクトップのテストは `tailorit.lang=ja` に固定している([architecture.md](architecture.md#適合テストと許可リスト))。

## ビルド時に Android の文言を同梱する

`desktop/app/build.gradle.kts` の `syncAndroidStrings`(#1759)。

| 元 | jar の中 |
|---|---|
| `android/renderer/src/main/res/values/strings*.xml`(日本語)・`values-en/strings*.xml`(英語) | `i18n/renderer/values…/…` |
| `android/app/src/main/res/values/strings*.xml`・`values-en/strings*.xml` | `i18n/app/values…/…` |
| (上の一覧) | `i18n/index.txt`(jar の中は一覧を引けないので書く) |
| `desktop/app/src/main/resources/i18n/desktop/values/strings_desktop.xml`・`values-en/strings_desktop.xml` | `i18n/desktop/…`(普通のリソース) |

- Android のファイルは写すだけで、デスクトップの repo には置かない。Android でキーを直せばデスクトップも同じキーで変わる
- `StringTable.fromClasspath` が `index.txt` の順(パスの名前順)に読み、最後にデスクトップの 2 ファイルを読む。同じキーは後に読んだ方で上書きされる
- パスに `/values-en/` があれば英語、`/values/` があれば日本語として読む
- XML は `AndroidStringsXml.parse` が `<string>` と `<plurals>` だけ読む。エスケープは `"…"` で囲んだ値・`\'` `\"` `\n` `\t` `\\` `\@` `\?` `\uXXXX`(`unescape`)

## 引き方

```kotlin
Strings["renderer_back"]
Strings.format("desktop_input_required", name)
Strings.plural("<plurals のキー>", count, count)
```

- 引けない時: 英語なら 英語 → 日本語 → キーそのもの。日本語なら 日本語 → 英語 → キーそのもの(`StringTable.order`)
- `format` は `String.format` を今の言語の `Locale` で呼ぶ
- `plural` は英語だけ `count == 1` で `one`、他は `other`。`<plurals>` が無ければ `<string>` を引く
- 画面に出すキーは `Strings[...]`・`Strings.format(...)`・`Strings.plural(...)` の形で書く(下のテストがこの形で拾う)

## 文言を足す時

1. Android に同じ意味の文言があれば、そのキーをそのまま使う(新しく作らない)
2. 無ければ `desktop/app/src/main/resources/i18n/desktop/values/strings_desktop.xml`(日本語)と `values-en/strings_desktop.xml`(英語)の両方に足す
3. 決まり(`StringsTest.desktopKeysAreSortedAndTheSameInBothLanguages` が見る)
   - キーは `desktop_` で始める
   - キーは名前順に並べる(1 行 1 キー)
   - 日本語と英語で同じキーを同じ順に持つ
4. コードで使ったキーが日本語・英語の両方にあるかは `StringsTest.everyKeyUsedInTheAppExistsInJapaneseAndEnglish` が見る。`plural` で引くキーは `<plurals>` に、`[]`・`format` で引くキーは `<string>` に置く(引き違えるとキーそのものが出る)

確かめる: `desktop/` で `./gradlew :desktop:test --tests '*i18n*'`。

## 日本語の直書きを許す時

`HardcodedJapaneseTest` が `desktop/app/src/main/kotlin` の文字列リテラルに日本語(ひらがな・カタカナ・漢字)があると落ちる。

- 見ない物: コメント、`System.err.println("…")`・`error("…")`・`throw X("…")`・`require(…) { "…" }`・`check(…) { "…" }` の直後のリテラル(人に出さない)
- それ以外で残してよい物は、テストの `allowed` に「`src/main/kotlin` からのパス → 文字列の集合」で足し、直前のコメントに理由を書く。今ある例: 適合テストの描画の木の値(iOS の日本語と突き合わせる)、表示しない聞き取りの辞書、モックの見本
- 画面に出す文言は許す一覧に足さず、上の「文言を足す時」で strings に移す

## 英語で確かめる

```sh
cd desktop
TAILORIT_LANG=en ./gradlew :desktop:run
```

- `gradlew run` に system property を渡す時は `JAVA_TOOL_OPTIONS=-Dtailorit.lang=en ./gradlew :desktop:run`
- 見る所: 足した文言が英語で出る・キーそのもの(`desktop_…`)が出ていない
- 日本語に戻すには `TAILORIT_LANG=ja`(OS が日本語なら外すだけでよい)
